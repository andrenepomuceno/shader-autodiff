# shader-autodiff

[English](README.md) · [Português (Brasil)](README.pt-BR.md) · [日本語](README.ja.md) · [简体中文](README.zh-CN.md) · **Русский**

Превращает математическое выражение, введённое во время выполнения, в GLSL/WGSL, который за один проход вычисляет его значение **и точные
производные**, а также соответствующий вычислитель на JavaScript для CPU. Без CAS, без этапа сборки,
без зависимостей, около 15 кБ.

## Установка

```bash
npm install shader-autodiff
```

Или напрямую из CDN, без этапа сборки (обычные ES-модули):

```js
import { compile } from 'https://cdn.jsdelivr.net/npm/shader-autodiff@0.1.0/src/index.js';
```

Объявления типов TypeScript поставляются в `types/index.d.ts`.

## Использование

```js
import { compile } from 'shader-autodiff';

const g = compile('(1 + a/(2*sqrt(r^2 + b^2)))^4', {
  variables: ['x', 'y', 'z'],          // differentiate with respect to these
  parameters: ['a', 'b', 't'],          // uniforms, not differentiated
  derived: { r: 'sqrt(x*x + y*y + z*z)' },
  order: 1,                             // 0 value, 1 gradient, 2 Hessian
});

g.glsl('conformal', { parameters: { a: 'u_params.x', b: 'u_params.y' } })
// float conformal(vec3 p, out vec3 gradient) { ... }
g.wgsl('conformal')                     // fn conformal(p: vec3<f32>, gradient: ptr<function, vec3<f32>>) -> f32
g.js('conformal')                       // source of the same function in JS
g.evaluate({ x, y, z, a, b, t })        // { value, gradient } computed from the same graph
```

Для узловых материалов three.js и `WebGPURenderer` вызов `g.tsl(TSL, { inputs: positionLocal, parameters })`
возвращает узлы TSL (`value`, `gradient`, …), построенные из того же графа.

`compile({ X: '…', Y: '…', Z: '…' }, …)` возвращает значения и якобиан, а `createProgram` — это
низкоуровневый API для структурированных выходов (несколько функций с общим графом, вложенные
производные, возвращаемые значения `mat3`). API и контракт генерируемого кода описаны в [docs/api.md](docs/api.md),
а то, как всё это тестируется, — в [docs/validation.md](docs/validation.md).

## Примеры

- [examples/three](examples/three/): рэймарчер на three.js для SDF, которые вы вводите сами; нормали берутся из
  точного градиента, а длина шагов масштабируется им (поэтому даже поля, не являющиеся расстояниями, марчатся безопасно). Запустите сервер из корня
  репозитория (`node tools/gpu/serve.mjs`) и откройте `/examples/three/`.
- [examples/metric-shaders](examples/metric-shaders/metric.js): метрические тензоры и их частные производные
  для трассировки геодезических лучей, включая метрики-обратные образы (pullback) из вложенных производных.

## Зачем

- **Точные и дешёвые производные на GPU.** Нормали SDF, частные производные метрики (символы Кристоффеля),
  якобианы деформаций, кривизна, шаги метода Ньютона. Конечные разности требуют 4–7 дополнительных вычислений
  и ε, который где-нибудь да окажется неверным.
- **Выражения, вводимые пользователем во время выполнения.** Живым редакторам (редакторам метрик, песочницам шейдеров, инструментам
  построения графиков) нужны безопасный парсер и кодогенерация прямо в браузере, а не офлайн-компилятор.
- **Один граф, любой бэкенд.** Вычислитель на CPU совпадает с шейдером: для тестов, выбора объектов (picking), семплирования,
  логики камеры.

## Устройство

1. **Парсер.** Небольшой парсер Пратта с грамматикой на основе белого списка: числа, именованные символы,
   `+ - * / ^`, унарный минус, вызовы функций из фиксированной таблицы. Ограничения на длину, глубину, число узлов
   и размер показателя степени (никаких башен степеней). Ошибки содержат позиции для подчёркивания в редакторе.
2. **AST → SSA DAG.** Хеш-консинг объединяет равные поддеревья (структурное CSE), константы сворачиваются,
   локальные тождества упрощаются, операнды коммутативных операций приводятся к каноническому порядку.
3. **Прямой режим во время кодогенерации.** Тангенсы (касательные) строятся как узлы графа, поэтому они разделяют
   подвыражения со значением и могут быть продифференцированы повторно (гессианы, метрики-обратные образы).
   Генерируемый код — **обычный скалярный/векторный код**: никаких дуальных структур во время выполнения, поэтому драйвер
   оптимизирует его как написанный вручную. Нулевые касательные отбрасываются: `∂/∂x` узла, который не
   зависит от `x`, никогда не генерируется. Градиенты упаковываются в `vecN`/`matN`, когда размеры подходят.
4. **Таблица правил.** Одна запись на операцию: правило для значения и правило для касательной. Субградиенты для
   `abs`/`min`/`max`, нулевая производная для `sign`/`floor`, целые степени как произведения, `pow` с
   переменным показателем через `log`.
5. **Эмиттеры.** GLSL ES 3.00 (WebGL2; также корректен для настольного GLSL 3.30+), WGSL, JS, узлы TSL для three.js. Вещественные литералы
   всегда с точкой, детерминированные временные переменные (`t0, t1, …`) для стабильных диффов и кэширования шейдеров.

## Аналоги и позиционирование

| Проект | Что это | Какую нишу закрывает эта библиотека |
| --- | --- | --- |
| [Slang](https://github.com/shader-slang/slang) | Полноценный язык шейдеров с прямым и обратным автоматическим дифференцированием; целевые платформы: GLSL, HLSL, SPIR-V, Metal, WGSL (экспериментально) | Тяжёлый нативный компилятор / компилятор на WASM, на входе исходный код шейдера; это не небольшая библиотека для формул, вводимых пользователем в браузере |
| [glsl-autodiff](https://github.com/sibaku/glsl-autodiff) | Заголовок GLSL с дуальными/гипердуальными типами и перегруженными функциями | GLSL нужно писать вручную; дуальные структуры во время выполнения; нет парсера и двойника на CPU |
| [Symbolic Differentiation in GPU Shaders](https://www.microsoft.com/en-us/research/publication/symbolic-differentiation-in-gpu-shaders/) (MSR 2011) | Производные как возможность компилятора HLSL | Исследование, а не доступный инструмент |
| [Vertex shader domain warping with AD](https://arxiv.org/pdf/2405.07124) (2024) | Хост-язык генерирует GLSL с производными | Та же идея, но это статья, а не переиспользуемая библиотека |
| [GradientScript](https://github.com/mfagerlund/gradient-script) | Преобразование формул градиента из исходного кода в исходный код | Вывод в GLSL неясен |
| [shader-ast](https://github.com/thi-ng/umbrella/tree/develop/packages/shader-ast), swizzler | DSL на TypeScript, компилируемые в GLSL/JS | Нет дифференцирования |

Ниша: **строка на входе, оптимизированный GLSL/WGSL с производными + JS на выходе, безопасно для пользовательского ввода, в
несколько килобайт.**

## Первый клиент

[metric-shaders](examples/metric-shaders/metric.js): адаптер заменяет компилятор метрик на sympy
(`metricTensor` + `metricPartials`), так что приложение может работать полностью статически. Каждый пресет метрики совпадает
со значениями sympy на CPU (с точностью до 1e-10) и на GPU (WebGL2 и WebGPU, в пределах точности float32).

## Планы

- Бенчмарки: стоимость на пиксель для значения + градиента у SDF и метрик; сгенерированный код против конечных
  разностей, против структур glsl-autodiff и против кода, сгенерированного sympy, на настольных и мобильных GPU.
- Страница-песочница: ввести формулу, увидеть код, построить график значения и градиента.
- Дополнительная оптимизация: вынесение общих множителей за скобки в суммах.
